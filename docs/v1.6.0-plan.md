**Status:** Implemented — automated checks and NVDA pass green; packaging pending · 2026-11-24
**Builds on:** v1.5.1 personalization and settings
**Scope:** two transient reading overlays — **focus mode** and the **reading ruler**. No page mutation, no history entries, no new permissions, and no settings-schema change.

The full browser harness passes (815 checks), including toolbar layout, accessibility-tree, forced-colors, history, and hostile-page checks. ## Goal

A reader can dim everything except the paragraph they are reading, and lay a translucent ruler under the pointer to keep their place. Both aids toggle independently from the toolbar, work after the toolbar is dismissed, and disappear on `Escape` or when the extension is turned off.

**Acceptance:** focus mode and the ruler toggle independently; neither changes page content, page styles, or undo history; focus follows the selection or caret and repositions on scroll/resize; the ruler follows the pointer without stealing clicks; both work with the toolbar hidden; `Escape` exits; dark, light, forced-colors, keyboard-only, 200% zoom, and a 320 px viewport all pass; the full harness is green.

## Scope decision: spacing is already shipped

The roadmap's Phase 5 bullet named line and paragraph spacing as “independent controls from the existing letter/word spacing.” That work shipped in **v1.5.0**: `lineHeight` and `paragraphSpacing` are separate saved values and separate sliders under the **Custom** spacing preset, applied by the existing `spacing` command. Letter and word spacing are separate values too.

v1.6.0 therefore does **not** add a second spacing model. It verifies the v1.5.0 paths and documents that paragraph spacing needs a block target. A one-press “line spacing” toolbar button is deferred: it would duplicate the preset command, add another toolbar button, and create two ways to set the same CSS property.

## Decisions

### 1. Focus mode is a spotlight overlay, not per-element opacity

- One fixed, transparent `<div>` is positioned over the focused block and given a very large `box-shadow` spread. Everything outside the block is dimmed; the block itself stays untouched.
- This mutates no page element, creates no history entry, and leaves Reset page alone.
- The alternative — setting `opacity` or a class on every other block — would rewrite page styles, fight the page's own CSS, and require undo/reset support.
- The overlay is `pointer-events: none` and `aria-hidden="true"`, so it never intercepts a click, selection, or screen-reader traversal.
- Dimming is theme-neutral: black at about 55% opacity works on light and dark pages. The focused block keeps its own colours.
- A single focused block is deliberate. When a selection spans several blocks, the block containing the **start** of the selection is used. Multi-block focus is deferred.

### 2. The reading ruler is a fixed band, not a text overlay

- A fixed `<div>` spans the viewport width and follows the pointer's vertical position. It is `pointer-events: none` and `aria-hidden="true"`.
- It does not use ranges or page geometry, so it keeps working across sites with unusual layout, inside tables, and over images.
- The band is centred on the pointer, with a soft top and bottom edge. It is hidden when the pointer leaves the page or on touch input.
- It sits below the toolbar and settings dialog in the stacking order, so extension UI stays readable.

### 3. Session-only state, no schema change

- `STATE.focusMode` and `STATE.readingRuler` live for the page session and reset on reload.
- These are transient reading aids, like read-aloud state, not page-styling defaults. Turning them on for every site from a synced preference would surprise users.
- No new storage keys, no `settingsSchemaVersion` bump, and no export/import changes.
- Persisting the aids is deferred; if added later it should be an explicit “remember on this site” preference.

### 4. Selection and caret drive focus; the pointer drives the ruler

- Focus mode resolves the block from the saved range, then the live selection, then the caret. If the user clicks into another paragraph, the spotlight moves with the caret.
- If the selection is collapsed and the caret is not in a text block, the last focused block is kept. The overlay does not flicker off on every stray click.
- Focus mode never follows the pointer. A moving spotlight makes reading harder, and it would fight the ruler.
- The ruler never uses the selection. It follows `pointermove` only, so the two aids can be used together without interfering.

### 5. Two toggle buttons in the existing reading group

```text
[Font] [Spacing] [Contrast] [Focus] [Ruler] [Read Aloud] [Stop]
```

- **Focus** uses `🎯`; **Ruler** uses `📏`. Both are icon buttons with `aria-label`, `data-tooltip`, `aria-pressed`, and `aria-keyshortcuts`.
- The tooltips name the shortcut and the behaviour: `Focus mode (Alt+Shift+D) · dims other paragraphs` and `Reading ruler (Alt+Shift+L) · follows the pointer`.
- The buttons stay in the same group as Read Aloud because they are reading aids, not page styling.
- Both are compact (36 px minimum) so the toolbar does not grow a third row on a 480 px viewport.

### 6. Keyboard shortcuts and Escape

- In-page `Alt+Shift+D` toggles focus mode and `Alt+Shift+L` toggles the ruler, matching the existing `Alt+Shift+B/H/R` pattern. They are ignored in editable fields and when the extension is disabled.
- `Alt+Shift+F` remains the manifest **Focus Toolbar** command and is not reused.
- `Escape` order: settings dialog → active reading → reading aids (turn both off) → toolbar. A second `Escape` after disabling the aids still closes the toolbar.
- The toolbar's ✕ button dismisses the toolbar **and** turns the aids off, because it is an explicit “clear this page's UI” action. Aids may remain when the toolbar disappears for another reason, such as the selection collapsing, which is what “works with the toolbar hidden” means.

## UX

### Focus mode

- Enabling it resolves the current block and shows the spotlight immediately. If no block can be resolved, show `Place the cursor in a paragraph or select text` and leave the toggle off.
- The spotlight updates on `selectionchange`, `scroll`, and `resize`, throttled with one `requestAnimationFrame`.
- When the focused block is detached by a page re-render, re-resolve from the current selection/caret on the next update. If none exists, hide the spotlight until the next selection.
- The focused block keeps its normal selection highlight and text selection.
- The toolbar and settings dialog sit above the scrim and are never dimmed.
- The spotlight has a subtle 1 px outline so the edge reads clearly on pages with a similar background. The outline is not a focus indicator and is `aria-hidden`.

### Reading ruler

- Enabling it shows the band at the last pointer position, or at the vertical centre of the viewport if the pointer has not moved yet.
- Height is about `2.2em` at the root font size, clamped to 28–56 px, so it covers one line of comfortably spaced text.
- It follows `pointermove` with a `requestAnimationFrame` guard. It ignores touch pointers and hides on `pointerleave` and window blur.
- It has a soft gradient and a thin top/bottom edge. It does not animate.
- The band stays put while the page scrolls; the text moves under it, which is the expected ruler behaviour.

### Toggles and announcements

- `aria-pressed="true"` on the active button, mirrored in `updateToolbarState()`.
- Toast on change: `Focus mode on`, `Focus mode off`, `Reading ruler on`, `Reading ruler off`. `aria-pressed` is the primary state for assistive tech; toasts are a secondary confirmation.
- If both aids are on, turning the toolbar's ✕ off announces `Reading aids off` once rather than two toasts.

## Architecture

New files:

- **`content-scripts/modules/reading-aids.js`** — DOM-free geometry and messages: ruler height, ruler clamping, spotlight rect insets, rect comparison, viewport intersection, and toggle text.
- **`content-scripts/modules/reading-aids-ui.js`** — resolves the focus block, creates and updates the two overlay elements, caches the ruler height, installs and removes the pointer/scroll/resize listeners, and owns the enable/disable transitions.

Touched files:

- `core.js`: `STATE.focusMode`, `STATE.readingRuler`, `STATE.focusBlock`; `CONFIG.focusOverlayId`, `CONFIG.readingRulerId`; the aid shortcuts in `SHORTCUT_LABELS` and `SHORTCUT_ARIA`. Ruler geometry lives in `reading-aids.js`; the dim opacity is a CSS value.
- `toolbar.js`: two buttons, update state from `STATE`, and keep the roving tab order working.
- `commands.js`: `toggleFocusMode` and `toggleReadingRuler`; the close command disables both.
- `app.js`: `Alt+Shift+D`/`Alt+Shift+L`, Escape ordering, selection-change hook, scroll/resize refresh, and cleanup when the extension or site rule turns off.
- `content.css`: overlay and ruler styling, light/dark edge treatment, forced-colors fallback, reduced motion, and print hiding.
- No manifest permission changes. `manifest.json` only changes its version at release.

### Overlay markup

The overlays are siblings of the toolbar under `getMountNode()`, not children of the `role="toolbar"` element. That keeps the toolbar's ARIA pattern valid and lets the aids outlive the toolbar.

```html
<div id="accessibility-focus-overlay" aria-hidden="true"></div>
<div id="accessibility-reading-ruler" aria-hidden="true"></div>
```

Neither element receives text, roles, or focus. They cannot be reached by Tab or a screen reader.

### Geometry

- The focus rect comes from `Element.getBoundingClientRect()` on the resolved block, not from the selection rect, so a two-line paragraph gets one stable hole instead of a ragged range shape.
- The rect is applied as fixed `top`, `left`, `width`, and `height`, with a small negative inset so text descenders and focus outlines are not clipped.
- The ruler top is `clientY - height / 2`, clamped to `0 … innerHeight - height`.
- All geometry is recomputed in viewport coordinates, so 200% zoom and browser zoom need no special handling.
- If the block is taller than the viewport, the spotlight fills the viewport and the scrim is effectively invisible. That is correct: the reader is already looking at the block.

## Accessibility contract

- The buttons have the accessible names **Focus mode** and **Reading ruler**, exposed pressed state, and `aria-keyshortcuts`.
- The overlays are `aria-hidden` and pointer-transparent; they never enter the accessibility tree or the tab order.
- State changes are announced through the existing toast (`role="status"`) and through `aria-pressed`.
- Keyboard-only path: select text, Focus Toolbar, arrow to **Focus mode**, activate, arrow to **Reading ruler**, activate, `Escape` to exit.
- The spotlight does not remove or restyle any page text, so screen-reader reading order and page semantics are unchanged.
- Forced colors: the scrim is replaced by a 2 px `Highlight` outline around the focused block, because translucent shadows are unreliable in forced-colors. The ruler becomes a `Canvas` band with `CanvasText` borders and reduced opacity.
- `prefers-reduced-motion`: no transitions or animations on either overlay.
- 200% zoom and 320 px width: the spotlight tracks the enlarged block, the ruler spans the viewport, and neither clips or covers the close button.
- Print: both overlays are hidden.

## Errors and edge cases

| Situation | Behaviour |
|---|---|
| No selection and no caret block | Toast “Place the cursor in a paragraph or select text”; focus mode stays off. |
| Selection spans several blocks | Focus the block containing the selection start; document the single-block rule. |
| Focused block detached by a re-render | Re-resolve on the next selection/scroll/resize; hide if nothing remains. |
| Page scrolls or viewport resizes | Recompute the spotlight rect and keep the ruler at the pointer's viewport Y. |
| Toolbar dismissed while an aid is on | Aids stay on; `Escape` exits them. |
| Toolbar ✕ pressed | Turn both aids off and dismiss the toolbar. |
| Settings dialog opens | Aids stay enabled but sit behind the dialog overlay; they return when it closes. |
| Extension or site rule turns off | Remove both overlays silently and reset the buttons. |
| Editable field | Shortcuts are ignored there; the toolbar does not appear for editable targets. |
| Touch device / no hover | The ruler shows at the viewport centre and does not follow; focus mode still works. |
| Page navigation or reload | Aids reset with the page; nothing persists. |
| Cross-origin iframe | Out of scope: the content script runs in the top frame only. |
| Page element with a huge z-index | It can paint above the scrim; the toolbar still sits above both. Documented, not fixable without shadow DOM. |
| Page with a transformed `<body>` | Fixed positioning is relative to the transformed ancestor, as with the existing toolbar; not a new limitation. |

## Risks and mitigations

| Risk | Mitigation |
|---|---|
| Scrim hides content the reader needs | One-block hole, pointer-transparent, instant toggle, `Escape` exits. |
| Box-shadow spotlight is expensive on large pages | One fixed layer, one rAF-throttled geometry update, no page style writes. |
| Focus jumps unexpectedly | Follow the block, not the pointer; keep the last block when the caret leaves text. |
| Ruler distracts or flickers | rAF throttle, hide on pointer leave/blur, no transition, touch ignored. |
| Toolbar crowding at 320 px | Compact 36 px icon buttons; test 320 px and 200% zoom; the toolbar already wraps. |
| Forced-colors drops the shadow | Explicit outline fallback and a bordered ruler. |
| Keyboard conflicts with pages | Alt+Shift modifiers, ignored in editable fields, documented in the tooltip. |
| Aids leak after the extension is disabled | Central `disableReadingAids({ silent: true })` called from the enabled-state handler. |

## Test plan

**Node**

- New `check-reading-aids.js`: ruler height and clamping, spotlight rect insets, rect comparison, viewport intersection, and toggle messages.

**Browser**

- New `check-v160.js` using the content script in the page world and `content.css`:
  - Buttons absent from a toolbar for an unsupported state? No — buttons always exist; assert names, pressed state, and tooltips.
  - Focus mode creates one overlay, dims outside the block, and does not change page HTML or computed styles.
  - Moving the caret updates the spotlight; collapsing the selection keeps it on.
  - Scroll and resize reposition the spotlight and do not throw.
  - Ruler follows `pointermove`, clamps at the viewport edges, hides on pointer leave, and ignores touch.
  - Both toggles work with the toolbar removed; `Escape` exits them before closing the toolbar.
  - Close-button path turns both off and dismisses the toolbar.
  - Disabling the extension or a site rule removes both overlays.
  - No history entry is created by either toggle; undo/redo and Reset page are unaffected.
