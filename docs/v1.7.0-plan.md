# v1.7.0 — Selection translation plan

**Status:** Approved · 2026-11-25
**Builds on:** v1.6.0 reading aids
**Scope:** translate the current selection or paragraph into a read-only panel using Chrome's built-in Translator API. No page mutation, no undo entry, and no extension-originated network request.

## Goal

A user selects text or a paragraph, activates **Translate**, and reads the result in a panel beside the toolbar. They can compare it with the original, copy it, or hear it read aloud in the target language.

**Acceptance:** selection and paragraph scopes work; the target language is remembered and synced; the first language-pack download shows progress and can be cancelled; unsupported pairs and failures are explained; the result carries the right `lang`/`dir` and is announced accessibly; the page DOM and undo history are unchanged; the button is absent when the API is missing or the page is not a secure context; the toolbar still fits two rows at 800/640/480 px while reading; dark, light, forced-colors, keyboard-only, and 200% zoom all pass; the full harness is green.

## Decisions

### 1. A read-only panel, not page replacement

- v1.7.0 never replaces page text. The original stays intact, so there is no inline-markup problem, no RTL layout risk for page content, and no new undo/reset machinery.
- “Replace selection” and whole-page translation are explicitly deferred. Replacing text needs a text-snapshot history type and a strategy for links and emphasis; page translation needs a DOM walk and a `MutationObserver`.
- A panel also lets the user compare the original and translation, which Chrome's page-level translation does not do well.

### 2. Chrome's built-in Translator API only

- Feature-detect `'Translator' in self`; the API requires **Chrome 138+ on desktop**.
- No cloud service, API key, cost, or extension-originated network request. Chrome downloads an on-device language pack when a pair is first used; the page text is not uploaded.
- **The API requires a secure context.** Verified on a non-secure LAN HTTP origin: `isSecureContext` is false and `Translator` is absent. On `http://` pages the button is not rendered. The fallback text must say “Translation needs Chrome 138 or newer on desktop, on an HTTPS page,” not only “Chrome 138+”.
- `minimum_chrome_version` stays **91**. Older Chrome simply does not show the button.
- A `Permissions-Policy: translator=()` block is pair- and timing-dependent, so it cannot hide the button without an async check. Show the button when the constructor exists; explain a policy block in the panel.
- The API is available in the extension's content script; verified on Chrome 156 during planning. Two facts from that run shape the UI: every supported pair currently reports `downloadable` even when cached (Chrome hides per-pair state), and `LanguageDetector` reports `unavailable`.

### 3. Selection first, paragraph on Shift

- Default scope is the current selection, matching the toolbar's existing selection model.
- **Shift-click** translates the block containing the selection, using `closestBlock()`. The keyboard shortcut always translates the selection; paragraph scope is a pointer modifier.
- Reuse `buildTextMap(range)` rather than `Range.toString()` so block and inline boundaries keep their word separators.
- `getScopeOverride()` returns `'block'` for `translate` when Shift is held. **Do not add `translate` to `BLOCK_COMMANDS`** — that set inverts the Shift meaning. Do **not** call `resolveScope()`: for a selection-scoped command it calls `wrapRange()`, which mutates the page. The translate command reads the text directly from the saved range (or `closestBlock()` for paragraph scope).
- The tooltip says: `Translate selection (Alt+Shift+G) · Shift-click: paragraph`.

### 4. The panel owns the target language

- A target-language `<select>` lives in the panel. There is no duplicate control in the options page or the in-page settings dialog in v1.7.0; the panel is where the setting is needed, and a duplicate would risk drift.
- The choice is stored in `chrome.storage.sync` as `translationTarget`, so it follows the profile.
- The source language is derived from the nearest `lang` attribute or the page language, with a manual override in the panel. Do not depend on `LanguageDetector`: it reported `unavailable` on the test Chrome build.
- The target default is `navigator.language`, normalized. If the normalized tag is not in Chrome's supported list, fall back to `en`. The same fallback applies to an imported or stored value.
- Chrome's published list has **39** tags today, including `zh` and `zh-Hant`. Pin the static table to the published list and record the source date in a comment; there is no API to enumerate pairs.

### 5. Non-modal dialog beside the toolbar

- `role="dialog"` with `aria-modal="false"`, labelled by its heading. Focus moves into the panel; Tab follows the normal document order, and Shift+Tab returns to the toolbar; `Escape` closes the panel first and returns focus to **Translate**. A second `Escape` closes the toolbar as before.
- Mount the panel as a sibling of the toolbar under `getMountNode()`, not inside the `role="toolbar"` container, so the toolbar's ARIA pattern stays valid. Add its ID to `isClickOutsideExtensionUi`, `SKIP_SELECTOR`, and the selection-change guard.
- Position it with JavaScript from the toolbar's rectangle. Choose the side with more room rather than only mirroring the toolbar, clamp it to the viewport, and cap its height with scrolling. Recalculate on scroll and resize in the toolbar's existing `requestAnimationFrame` pass.
- The panel is a snapshot: its contents do not change when the page selection changes. **A new non-collapsed selection outside the panel closes the panel** and lets the toolbar follow the new selection. Collapsing the selection, or selecting inside the panel, keeps it open.
- **Teardown:** `removeToolbar()` closes the panel too. That covers the toolbar ✕, Escape-to-toolbar, extension off, Reset page, and outside click. Note that `createToolbar()` calls `removeToolbar()` first, so recreating the toolbar closes the panel by design.
- `applyTheme()` must toggle the panel's `light-mode` class as well as the toolbar's and the settings dialog's.
- The panel sits above the focus-mode scrim (z-index at or above the toolbar) and is hidden by `@media print`.
- **Page-style isolation:** the panel and its descendants need an explicit reset and explicit colours, fonts, and sizing so hostile page CSS cannot restyle the controls. Extend `check-toolbar-isolation.js`.
- **RTL pages:** set `direction: ltr` and `lang="en"` on the panel chrome (the UI is English); keep `dir="auto"` on the translation result and the original text.
- The close button, Escape, and clicking outside the extension UI all close the panel. Closing does not stop speech that is already playing; the toolbar's **Stop Reading** remains available.

### 6. Plain text, 5,000-character cap

- Use `Translator.translate()` for v1.7.0. Streaming is deferred so the result is announced once, not on every chunk.
- Cap input at **5,000 characters** after collapsing runs of spaces and tabs while keeping single paragraph breaks. Longer input shows the character count and asks the user to select less text or use the paragraph scope.
- Links, emphasis, lists, and line breaks are flattened in the panel. Keep paragraph breaks with `white-space: pre-wrap`. This is documented; the original remains on the page.

## UX

### Toolbar

Add one icon button to the existing reading group, before **Read Aloud**:

```text
[Font] [Spacing] [Contrast] [Translate] [Read Aloud] [Stop]
```

- Visible label: `文A` (the conventional translate glyph), with `aria-label="Translate"`.
- Tooltip: `Translate selection (Alt+Shift+G) · Shift-click: paragraph`.
- `aria-haspopup="dialog"` and `aria-expanded="true|false"` on the button.
- While a request is in flight, set `aria-busy="true"` but **keep the `文A` glyph**. Replacing it with `…` changes the button width and can reflow the tight 480 px layout. Progress is announced by the panel's status line.
- Add the in-page **`Alt+Shift+G`** shortcut beside the existing Alt+Shift+B/H/R/D/L shortcuts. It is ignored in editable fields and when there is no saved selection, and it always uses the selection scope. Do **not** use `Alt+Shift+T`: Chrome reserves `Shift+Alt+T` for focusing the browser toolbar, so the page never receives it.

**Fit step (required).** The planned markup does not fit two rows at 800 px and 480 px while reading; the settings group wraps to a third row. Add:

```css
#accessibility-toolbar .reading-group { gap: 0; padding: 0; }
#accessibility-toolbar .settings-btn { min-width: 32px; }
```

Measured with the exact `check-qol-toolbar.js` page and row counter: two rows at 800/640/480, idle and reading, with a 32 px minimum target. Do not shrink below 32 px. `padding: 0 2px` misses the 480 px reading row by 2 px; keep it at zero.

### Panel

```text
┌ Translation ──────────────────────── ✕ ┐
│ From [Auto (Spanish) ▾]  To [English ▾] │
│ Preparing language pack… 42%  [Cancel]  │
│                                         │
│ <translated text, lang="en" dir="auto"> │
│                                         │
│ ▸ Original text                         │
│ [Copy] [Read aloud]                     │
└─────────────────────────────────────────┘
```

- Header: **Translation** and a close button.
- Language row: source and target selects with visible labels. Stack them on narrow viewports.
- Status line: `role="status"` and `aria-live="polite"` for “Translating…”, download progress, “Translation ready”, and copy confirmation. Throttle progress announcements to 25% steps.
- Download: show “Preparing language pack…” as soon as `create()` starts. Only switch to a percentage when a `downloadprogress` event actually arrives; a cached pair may resolve with no events. Provide an explicit **Cancel** control while preparing.
- Result: plain text with `lang` set to the target and `dir="auto"`. Focusable (`tabindex="0"`) so keyboard users can scroll a long result. The result is not a live region, so it is not re-announced on every update.
- **Original text** is a collapsed `<details>` block, also carrying its own `lang` and `dir`.
- **Copy** and **Read aloud** are inactive until a result exists. Prefer `aria-disabled="true"` with a no-op click so the controls stay focusable and their unavailable state can be announced; a plain `disabled` button is skipped by the keyboard and is not announced.
- Errors use a dedicated `role="alert"` element and offer **Try again** with focus moved to it. Changing either language cancels the current request and starts a new one.
- Copy uses `navigator.clipboard.writeText` in the click handler. If the API is unavailable or denied, select the result and tell the user to press Ctrl/Cmd+C. Confirm success in the status line.
- Read aloud uses the target language for chunking, sentence splitting, and voice choice. If page reading is already active, stop it first. The panel's button reflects pause/resume, or is disabled while reading, so it does not start a second session.

### Focus and selection guards

- Opening the panel focuses the panel container (`tabindex="-1"`) so the screen reader announces the dialog and its label; Tab then reaches the close control, language selects, and actions. Put the close button last in DOM order and place it top-right with CSS so it does not steal the first Tab stop.
- Selection changes: if the panel is open and a new, non-collapsed range lies outside the panel, close the panel and let `handleSelectionChange` continue so `STATE.savedRange` and the toolbar position update. A collapsed selection or a range inside the panel is ignored.
- Add the panel ID to the `activeElement.closest(...)` check in `handleSelectionChange` as well as `STATE.translationOpen`.
- Prevent the default and stop propagation on `mousedown` for panel buttons (but not the selects), so Copy, Read aloud, and Close do not collapse the page selection. The panel is outside the toolbar, so it does not inherit the toolbar's handler.
- Because the panel is outside the toolbar element, its selects keep native arrow-key behavior and the toolbar's roving handler does not see them.
- Escape order: **settings dialog → translation panel → active reading → reading aids → toolbar**. The panel branch must **not** be gated by `isEditableTarget()`: a `<select>` counts as editable, so Escape would not close the panel from the language controls.
- The toolbar ✕, Escape, and clicking outside the extension UI all close the panel (outside-click still keeps the toolbar open while speech is playing). Closing does not stop speech that is already playing; the toolbar's **Stop Reading** remains available.

## API handling

- `Translator.availability({sourceLanguage, targetLanguage})` returns `available`, `downloadable`, `downloading`, `unavailable`, or **`null`** when support cannot be determined. Treat `null` as unavailable with the generic explanation.
- `unavailable` also covers the same-language case and a `Permissions-Policy` block. Do the same-language check before calling the API and explain a policy block in the panel.
- Call `Translator.create()` directly from the click path so the first download has user activation. Do not `await` a slow operation before it; transient activation can expire. `NotAllowedError` means activation was lost or the download was blocked — tell the user to press Translate again.
- Pass **two** abort signals. A create signal aborts only if the panel closes or a language changes before creation finishes. A separate per-request signal aborts the current `translate()` call. Aborting the create signal **after** creation resolves is equivalent to `destroy()`, so never reuse it to cancel a translation; evict a destroyed translator from the cache and create a new one on demand.
- Cache one translator per language pair for the page lifetime, keyed by normalized source and target.
- Translation calls are sequential. Disable duplicate submissions rather than queueing them.
- Normalize BCP 47 tags before use: strip most regions (`pt-BR` → `pt`), map `zh-CN` → `zh`, `zh-TW`/`zh-HK` → `zh-Hant`, and `nb` → `no`. Persist the normalized tag. Tags outside the supported list fall back to `en`.
- Supported languages come from Chrome's published list (39 today, including `zh-Hant`). If Chrome adds pairs, they can be added to the static table; there is no API to enumerate them.
- If the source and target are the same, show “This text is already in <target language>” and do not call the API.
- A translation that is in flight when the tab becomes inactive can reject with `InvalidStateError`; show “Translation paused because the tab was in the background” with **Try again**.
- Map errors explicitly: `NotAllowedError` (blocked or lost activation), `NotSupportedError` (pair unsupported), `NetworkError` (download failed or offline), `AbortError` (user cancelled — silent), `InvalidStateError` (inactive document), `QuotaExceededError` (text too long), and `OperationError`/`UnknownError` (generic failure + retry).

## Architecture

New files:

- **`content-scripts/modules/translation.js`** — DOM-free language table, normalization, target default, availability/create/translate wrapper, translator cache, separate abort signals, and error mapping. Accepts an injectable translator factory so it can be unit-tested in Node. It must not import `core.js` or touch `navigator` at module scope; pass the 5,000-character cap in so the test can import it directly.
- **`content-scripts/modules/translation-ui.js`** — panel markup, language controls, status/result rendering, copy, read-aloud wiring, focus handling, viewport placement, and page-style isolation.

Touched files:

- `core.js`: panel ID, input cap, `STATE.translationOpen`, `SHORTCUT_LABELS.translate`/`SHORTCUT_ARIA.translate`.
- `toolbar.js`: conditional button, command routing, tooltip, panel ID in `isClickOutsideExtensionUi`, panel theming in `applyTheme()`, panel teardown in `removeToolbar()`, and a panel reposition hook.
- `commands.js`: `translate` command; no history entry; `closeToolbar()` relies on the new teardown.
- `scope.js`: Shift maps `translate` to block scope; do not add it to `BLOCK_COMMANDS` and do not route it through `resolveScope`.
- `app.js`: selection guard, close-on-new-selection, `Alt+Shift+G`, close on outside click, `translationTarget` load and `storage.onChanged`.
- `reading.js`: extract a text-based path (`beginReading({text, map, language})`); add `session.language`, use it for `utterance.lang`, and give `pickReadingVoice(language)` a language argument. An empty `map.entries` is already safe because `rangeFromOffsets()` returns null.
- `prefs.js`: `translationTarget` in `SYNC_KEYS`.
- `settings-io.js`: `translationTarget` in `PREFERENCE_KEYS`, `buildSettingsFile`, and normalization on parse.
- `settings.js`: export argument, import whitelist, reset-to-defaults.
- `options/options.js`: state, load, export argument, import whitelist. No options-page control; read a fresh value at export time or subscribe to storage so an open options page does not export a stale target.
- `content.css`: panel, light/dark, forced-colors, 320 px, reduced motion, print, page-style isolation, and the toolbar fit step.
- `manifest.json`: no change. `content-scripts/modules/*.js` already covers new modules.

## Accessibility contract

- The button has the accessible name **Translate**, `aria-haspopup="dialog"`, `aria-expanded`, and the tooltip names both scopes and the shortcut.
- The panel is a labelled dialog; focus moves in and returns to the button on close. The close control is reachable without stealing the first Tab stop.
- Source and target selects have programmatic labels; language names are readable English names.
- The result has `lang` and `dir="auto"` so screen readers use the right pronunciation and direction. The English UI chrome carries `lang="en"`.
- Progress is polite; errors are assertive; the result is not re-announced on every chunk.
- Unavailable Copy and read-aloud actions are focusable with `aria-disabled` and are not silently skipped.
- Keyboard-only path: select text, focus the toolbar, activate Translate, change languages, copy, read, close.
- Forced-colors uses `Canvas`/`CanvasText` for the panel, `ButtonFace`/`ButtonText` for controls, and `Highlight` for focus.
- Works at 200% zoom and on a 320 px-wide viewport without clipping the close button or the result.
- An RTL page does not mirror the panel chrome; the translation result follows its own `dir="auto"`.

## Errors and edge cases

| Situation | Behaviour |
|---|---|
| `Translator` missing, or the page is not a secure context | Hide the button; if invoked, toast: “Translation needs Chrome 138 or newer on desktop, on an HTTPS page.” |
| `Permissions-Policy` blocks the API | Panel message: “Translation is blocked on this page.” Keep the toolbar working. |
| Pair unavailable | Panel message: “Chrome can't translate Spanish to English yet.” Keep the selects usable. |
| First download | “Preparing language pack…” plus progress when events arrive and a **Cancel** control. Needs the originating click. |
| Download fails or offline | “The language pack couldn't download. Check your connection and try again.” + **Try again**. |
| Same source and target | “This text is already in <language>.” No API call. |
| Empty selection | Toast: “Select text or a paragraph to translate.” |
| Over 5,000 characters | Message with the count; suggest a smaller selection or Shift paragraph. |
| Source language unknown | Select “Auto” shows “Choose the source language”; Translate stays disabled until chosen. |
| Translation returns empty | Treat as an error and offer retry. |
| Selection detached by a re-render | Capture the text at open time; if the range is gone, use the live selection or ask for a new one. |
| New page selection while the panel is open | Close the panel; let the toolbar follow the new selection. |
| Collapsed selection while the panel is open | Keep the panel and toolbar open. |
| Page navigates or content script unloads | Panel disappears with the page; no persistence. |
| Clipboard denied or insecure page | Select the result and prompt for Ctrl/Cmd+C. |
| Editable field | Do not open; the toolbar does not appear for editable targets. |
| Cross-origin iframe | Out of scope: the content script runs in the top frame only. |

## Risks and mitigations

| Risk | Mitigation |
|------|------------|
| API availability varies by Chrome version, policy, secure context, or page `Permissions-Policy` | Feature-detect, explain the secure-context requirement, never break the rest of the toolbar; test a blocked page |
| First-use download is slow or fails | “Preparing” state that does not depend on a progress event, percentage when available, cancel, retry, offline message |
| Aborting a translation destroys a cached translator | Separate create and request signals; evict on destroy and recreate on demand |
| Language coverage is incomplete | Static 39-tag table, explicit fallback to `en`, and a pair-specific message |
| Machine translation quality | Label the result as machine translation; keep the original one click away |
| Panel covers page text | Viewport clamping, side-with-room flip, max-height with scrolling, close button |
| Toolbar crowding | Verified fit step (reading-group gap 0, settings 32 px); two-row assertions at 800/640/480 idle and reading. 320 px is a no-clipping check, not a row-count check |
| Selection/focus interactions remove the toolbar or act on a stale range | Close the panel on a new page selection; keep it for collapse/in-panel selection; `mousedown` prevention; panel added to the outside-click check |
| Hostile page CSS restyles the panel | Explicit reset and explicit properties; extend the isolation test |
| Reading refactor regresses page reading | Keep existing reading tests and add text-session tests |
| Schema bump breaks old import tests | Update the two schema assertions and add a schema 3 → 4 import case |
| Privacy wording drifts | State that the extension sends nothing; Chrome downloads the pack; qualify the README's “no network request” line |
