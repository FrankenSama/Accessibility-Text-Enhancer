# v1.7.0 — In-place selection translation plan

**Status:** Approved, implemented, and packaged · 2026-11-25 (in-place revision); release pending the manual NVDA pass
**Builds on:** v1.6.0 reading aids
**Scope:** replace the selected text, or the paragraph on Shift-click, with its translation in place, using Chrome's built-in Translator API. The original is restored by the Translate toggle, Undo/Redo, or Reset page. No result panel, no side-by-side copy view, and no extension-originated network request.

## Goal

A user selects text or a paragraph and activates **Translate**. The selected text is replaced where it sits by the translation, so the page keeps its shape and the reader keeps their place. The translated text is visually marked, can be heard with Read Aloud in the target language, and can be swapped back to the original.

**Acceptance:** selection and paragraph scopes work in place; the translated text carries `lang` and `dir="auto"`; Translate toggles back to the original; Undo/Redo and Reset page restore it; the target language is remembered and synced; the first use shows a compact language bubble; language-pack progress can be cancelled; unsupported pairs and failures are explained; the page DOM change is a normal undoable entry; the button is absent when the API is missing or the page is not secure; the toolbar still fits two rows at 800/640/480 px while reading; dark, light, forced-colors, keyboard-only, RTL, and 200% zoom all pass; the full harness is green.

## Decisions

### 1. In-place replacement, not a result panel

The panel from the first revision was safe but visually heavy. This revision replaces the selection in place: the translation occupies the same text flow, uses the page's font and size, and carries a subtle dotted underline. There is no separate result, original, copy, or read-aloud panel.

The page is mutated, so translation is a first-class page change:

- the original fragment is stored with the translation;
- Undo/Redo and Reset page restore it;
- pressing **Translate** on the translated text restores the original immediately;
- the toolbar's ✕ leaves the translation in place, exactly as it leaves a bold or highlighted change.

A page re-render can discard the change; that is the same limitation as the existing styling commands.

### 2. Flatten the selection, preserve surrounding context

The selected range is extracted as one fragment and replaced by one inline wrapper containing the translated string. This gives a coherent translation and avoids per-text-node sentence fragments.

- If the selection sits entirely inside a link or an emphasis element, the wrapper is inserted inside that element, so the link target or emphasis survives.
- If the selection spans several inline elements, the translation is plain text inside the wrapper; internal links and emphasis are not preserved visually. The original comes back through the toggle or Undo.
- A selection spanning several blocks is rejected in v1.7.0 with a short message. Shift-click already translates the whole paragraph. Per-block replacement is deferred.

### 3. One wrapper, one history record, one toggle

The wrapper is `span[data-atx-translation="<target>"]` with `lang="<target>"` and `dir="auto"`. It is inline, inherits the page's font and size, and gets a dotted underline so it is identifiable without looking like a page control.

The record stores the wrapper, the original nodes, the parent, the next sibling, the source and target, and whether the translation is currently showing. The same record powers:

- the Translate/Show original toggle;
- Undo/Redo (a translation entry is pushed for translate and for restore);
- Reset page (every record restores its original fragment).

After translation the wrapper's contents remain selected and the toolbar stays, so the button immediately becomes **Show original**. A new page selection leaves the translation in place and moves the toolbar to the new text.

### 4. Saved target, first-use bubble, Settings control

- The target lives in `chrome.storage.sync` as `translationTarget`.
- Once a target is saved, **Translate** starts immediately with that target.
- If no target is saved, the source is unknown, or the text is over the cap, a compact non-modal bubble appears beside the toolbar. It contains the source and target selects, the status/error, and Translate/Cancel or Try again.
- The same bubble shows language-pack progress and Cancel. It is not a result panel and closes when the text is replaced.
- A **Translation** target select is added to the in-page Settings dialog and the options page. That is the deliberate way to change the language later.
- The source is detected from the nearest `lang` attribute or the page language and can be overridden for the current request. It is session-only.

### 5. Chrome's built-in Translator API only

- Feature-detect `'Translator' in self`; Chrome **138+ on desktop** is required.
- **The API requires a secure context.** On `http://` pages the button is absent and the fallback text says "Chrome 138 or newer on desktop, on an HTTPS page".
- `minimum_chrome_version` stays **91**; older Chrome simply hides the button.
- No cloud service, API key, cost, or extension-originated network request. Chrome downloads an on-device language pack on first use; page text is not uploaded.
- A `Permissions-Policy: translator=()` block is pair- and timing-dependent, so it cannot hide the button without an async check. Show the button when the constructor exists and explain a policy block in the bubble.
- `availability()` may return `null`; treat it as unavailable. `unavailable` also covers same-language and policy blocks.
- Every supported pair currently reports `downloadable` even when cached, and `create()` may resolve with no `downloadprogress` event. The UI must show "Preparing language pack…" immediately and only add a percentage when an event arrives.
- `create()` needs transient activation. Map `NotAllowedError` to "click Translate again".
- Use **two** abort signals: a create signal for closing the bubble or changing the language before creation finishes, and a per-request signal for cancelling the `translate()` call. Aborting the create signal after creation destroys the instance; evict it and recreate on demand.
- Cache one translator per language pair for the page lifetime. Translation calls are sequential; cancel and restart rather than queueing.

## UX

### Toolbar

The Translate button keeps the `文A` glyph and sits before Read Aloud. Its state is dynamic:

| State | Glyph | Accessible name | Tooltip | ARIA |
|---|---|---|---|---|
| No target saved | `文A` | Translate | `Translate (Alt+Shift+G) · Choose a language` | `aria-haspopup="dialog"`, `aria-expanded` while the bubble is open |
| Target saved, text not translated | `文A` | Translate | `Translate to English (Alt+Shift+G) · Shift-click: paragraph` | `aria-pressed="false"` |
| Current selection translated | `↺` | Show original | `Show original (Alt+Shift+G)` | `aria-pressed="true"` |

- Add the in-page **Alt+Shift+G** shortcut beside B/H/R/D/L. It is ignored in editable fields and when there is no saved selection, and always uses selection scope.
- Do **not** use `Alt+Shift+T`: Chrome reserves `Shift+Alt+T` for focusing the browser toolbar.
- Clicking Translate with a saved target starts the request immediately. Clicking it with no target opens the language bubble. Clicking it on translated text restores the original.
- The toolbar's Translate button state is refreshed whenever the selection or the target changes, and after translation/undo/redo/reset.
- The fit step from the first revision stays: `.reading-group { gap: 0; padding: 0; }`, `.settings-btn { min-width: 32px; }`. Measured two rows at 800/640/480, idle and reading.
- The toolbar's ✕, Escape-to-toolbar, extension off, and Reset page close the bubble. They do not remove a translation that is already in the page.

### Translated text

- The wrapper is inline and inherits the surrounding font, size, weight, and colour.
- A subtle dotted underline marks it: `text-decoration: underline dotted`, 1 px, offset 2 px, in a muted green/blue. In forced-colors the line uses `Highlight`.
- `lang` is the target; `dir="auto"` follows the translated text. A page `span[data-atx-translation]` rule keeps it inline against hostile page CSS.
- The wrapper is ordinary page text: selectable, copyable, findable, and read by the page's Read Aloud. It is not a button, link, or focus stop.
- The status line announces "Translated to English. Press Alt+Shift+G again or Undo to restore." The wrapper itself is not a live region.

### Language bubble

```text
┌ Translate ────────────────────── ✕ ┐
│ From [Auto (Spanish) ▾]  To [English ▾] │
│ Preparing language pack… 42%  [Cancel]  │
│ [Translate] or [Try again]              │
└─────────────────────────────────────────┘
```

- Non-modal dialog, labelled **Translate**, mounted beside the toolbar under the mount node.
- Source and target selects with visible labels; they stack on narrow viewports.
- Status line `role="status"` and `aria-live="polite"`; errors `role="alert"`; Cancel while preparing; Try again on a retryable failure.
- The first-use/language bubble focuses the source select or the Translate button. The progress state focuses Cancel. Escape closes the bubble and cancels the request; focus returns to the toolbar button.
- Changing either select cancels a request in flight and starts a new one. The target is saved when Translate succeeds.
- The bubble is a sibling of the toolbar, not inside the `role="toolbar"` container. Its ID goes into `isClickOutsideExtensionUi`, `SKIP_SELECTOR`, and the selection guard.
- Position it from the toolbar/selection, choose the side with room, clamp it to the viewport, and cap its height. Recalculate on scroll/resize in the toolbar's existing RAF pass.
- It is hidden by `@media print`; the translated text stays in the printed page.
- `applyTheme()` themes the bubble.
- `removeToolbar()` closes the bubble but leaves the translated text.
- Reset page closes the bubble and restores every translation.

### Target language controls

- In-page Settings gains a **Translation** target select in the Reading settings card (or its own small card), listing the 39 supported languages.
- The options page gains the same target select in a **Translation** section.
- Both read/write `translationTarget` through the existing sync/storage path. The toolbar tooltip and the first-use bubble update from `storage.onChanged`.
- No source control outside the bubble; the source is session-only.

## API handling

- Normalize BCP 47 tags: strip most regions (`pt-BR` → `pt`), map `zh-CN` → `zh`, `zh-TW`/`zh-HK` → `zh-Hant`, `nb`/`nn` → `no`. Tags outside the 39-tag list fall back to `en` for a saved target and are empty for an undetected source.
- Same-language check before calling the API; name the language in the message.
- Input cap: **5,000 characters** after collapsing spaces/tabs and keeping single paragraph breaks. Over-cap shows the count and asks for less text or Shift-click. The message survives a language change.
- Map errors explicitly: `NotAllowedError` (blocked/lost activation), `NotSupportedError` (pair unsupported), `NetworkError` (download failed/offline), `AbortError` (cancelled, silent), `InvalidStateError` (tab backgrounded), `QuotaExceededError` (too long), `OperationError`/`UnknownError` (generic + retry).
- A cached pair may resolve without progress events; never wait for one before replacing the text.
- A background tab can reject a translation with `InvalidStateError`; offer Try again.

## Architecture

New file:

- **`content-scripts/modules/translation-inline.js`** — in-place replacement, wrapper record, toggle, history entry, compact language/progress/error bubble, first-use target, button state, bubble placement, teardown. The DOM-free language/service logic stays in `translation.js`.

Touched files:

- **`core.js`**: `translationWrapperAttr`, bubble ID, `STATE.translations` Map, `STATE.translationBubbleOpen`, `STATE.translationTarget` (empty until first use), shortcut labels.
- **`toolbar.js`**: dynamic Translate button state, bubble in `isClickOutsideExtensionUi`, bubble theming/teardown, translation state hook, button toggle.
- **`commands.js`**: `translate` → `translateSelection(scope)`; close/reset bubble.
- **`scope.js`**: Shift still maps `translate` to block scope; do not add it to `BLOCK_COMMANDS` and do not call `resolveScope`.
- **`history.js`**: translation history entry type; undo/redo insert/remove the wrapper and original nodes; Reset page restores every record; `hasPageChanges` sees translations.
- **`app.js`**: selection guard, bubble close on a new page selection, `Alt+Shift+G`, Escape order, outside click, target load/onChanged (empty means first use).
- **`reading.js`**: derive the reading language from the selected range's nearest `lang` (the wrapper) and use the target voice; prefer a matching voice for translated text. Remove the panel-only `startReadingText`/origin path if it has no caller.
- **`prefs.js`/`settings-io.js`**: target already wired; keep schema 4. Target empty on a fresh install until the first-use bubble saves it.
- **`settings.js`/`options/options.js`**: add the target select, load/save/onChanged, and import/export (already includes the target).
- **`content.css`**: wrapper underline/forced-colors/inline reset; compact bubble, light/dark, forced-colors, 320 px, reduced motion, print; remove the old result-panel styles; keep the toolbar fit.
- **`translation-ui.js`**: remove the result panel; the file is replaced by `translation-inline.js`. The old tests are replaced.
- **`manifest.json`**: no change; modules are already a web-accessible wildcard.

## Storage and schema

| Key | Values | Default |
|-----|--------|---------|
| `translationTarget` | normalized BCP 47 tag from the supported list | empty until the first-use bubble saves it; the bubble proposes `navigator.language` normalized, else `en` |

- Keep `CONFIG.settingsSchemaVersion` at **4**; `translationTarget` is already exported under `preferences`.
- Older schema files import their known keys and leave the current target unchanged.
- The source is session-only and not exported.
- No page text, translation result, or original fragment is stored outside the page session. The original fragment lives in memory until Undo/Reset or the page unloads.

## Accessibility contract

- The button has the dynamic name/tooltip above, `aria-pressed` for the translated state, and `aria-haspopup`/`aria-expanded` only while the language bubble is a dialog.
- The translated wrapper carries the target `lang` and `dir="auto"`; it is ordinary inline text in the reading order.
- The bubble is a labelled non-modal dialog; focus moves in, Escape closes/cancels, and focus returns to the toolbar button.
- Status is polite; errors are assertive; Try again/Cancel are keyboard reachable.
- The translated text is read with the target voice by Read Aloud; a saved voice for another language is not used.
- Keyboard path: select text, translate, hear the status, toggle back, Undo/Redo, change the target in Settings.
- Forced-colors uses system colours for the bubble and `Highlight` for the wrapper line; 200% zoom and 320 px do not clip the bubble.
- An RTL translation uses `dir="auto"` inside the existing page flow; the page layout may reflow, but the text direction is correct.

## Errors and edge cases

| Situation | Behaviour |
|---|---|
| API missing or page not secure | Hide the button; shortcut/toast: "Translation needs Chrome 138 or newer on desktop, on an HTTPS page." |
| `Permissions-Policy` blocks the API | Bubble: "Translation is blocked on this page." |
| Pair unavailable | Bubble: "Chrome can't translate Spanish to English yet." Keep the selects usable. |
| First download | "Preparing language pack…" immediately, percentage when events arrive, Cancel, and the target is not replaced until success. |
| Download fails/offline | Bubble: "The language pack couldn't download…" + Try again. |
| Same source and target | Bubble/toast names the language; no API call. |
| Empty selection | Toast: "Select text or a paragraph to translate." |
| Over 5,000 characters | Bubble reports the count and suggests less text or Shift-click; no API call. |
| Source unknown | Bubble asks for the source; Translate stays disabled until chosen. |
| Translation returns empty | Error + Try again; the page is unchanged. |
| Selection spans blocks | Toast: "Select text within one paragraph, or Shift-click to translate the paragraph." |
| Selection detached by a re-render | Ask for a new selection; no translation entry. |
| New page selection while the bubble is open | Close/cancel the bubble; the toolbar follows the new selection. A translation already in the page stays. |
| Page navigates/unloads | The translation and its in-memory original disappear with the page. |
| Clipboard | Not applicable; the translated text is ordinary selectable page text. |
| Editable field | The toolbar does not appear; no translation. |
| Cross-origin iframe | Top frame only. |

## Risks and mitigations

| Risk | Mitigation |
|---|---|
| In-place replacement breaks page layout or a link | Wrapper is inline; surrounding link/emphasis is preserved; flattening documented; original restored by toggle/Undo/Reset. |
| Page re-renders discard the translation | Same limitation as styling; the toolbar/Undo reflect the detached change; Reset restores what remains. |
| Multi-block selections | Reject with a clear message; Shift-click paragraph covers the common case. |
| API availability varies by version, policy, secure context, or `Permissions-Policy` | Feature-detect; explain; never break the rest of the toolbar. |
| First-use download is slow | Immediate "Preparing" state, progress when available, Cancel, retry, no text replacement until success. |
| Aborting a translation destroys a cached translator | Separate create/request signals; evict destroyed instances and recreate. |
| The target is wrong for the page | Source auto-detection with a manual override in the bubble; target select in Settings/options; tooltip names the target. |
| Translated text is mistaken for page text | Dotted underline, status announcement, toggle/Undo; no persistent background. |
| Toolbar crowding | Verified fit step; two-row assertions at 800/640/480 idle and reading. |
| Hostile page CSS styles the wrapper/bubble | Wrapper is inline with an explicit rule; bubble has its own reset/colours; isolation test. |
| Undo/Redo and the toggle disagree | One record with a translated/original side; both paths apply the same side and update the selection; Reset uses the record. |
| Read Aloud uses the source language | Derive the reading language from the wrapper's `lang`; strict voice matching. |
| Privacy wording drifts | State that the extension sends no page text; Chrome downloads the pack; translation changes the page locally and can be undone. |
