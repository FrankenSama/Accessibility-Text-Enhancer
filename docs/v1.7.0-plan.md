# v1.7.0 — Selection translation plan

**Status:** Draft for review · 2026-11-24
**Builds on:** v1.6.0 reading aids
**Scope:** translate the current selection or paragraph into a read-only panel using Chrome's built-in Translator API. No page mutation, no undo entry, and no network request from the extension.

## Goal

A user selects text or a paragraph, activates **Translate**, and reads the result in a panel beside the toolbar. They can compare it with the original, copy it, or hear it read aloud in the target language.

**Acceptance:** selection and paragraph scopes work; the target language is remembered and synced; the first language-pack download shows progress and can be cancelled; unsupported pairs and failures are explained; the result carries the right `lang`/`dir` and is announced accessibly; the page DOM and undo history are unchanged; the button is absent when the API is unavailable; dark, light, forced-colors, keyboard-only, and 200% zoom all pass; the full harness is green.

## Decisions

### 1. A read-only panel, not page replacement

- v1.7.0 never replaces page text. The original stays intact, so there is no inline-markup problem, no RTL layout risk, and no new undo/reset machinery.
- “Replace selection” and whole-page translation are explicitly deferred. Replacing text needs a text-snapshot history type and a strategy for links and emphasis; page translation needs a DOM walk and a `MutationObserver`.
- A panel also lets the user compare the original and translation, which Chrome's page-level translation does not do well.

### 2. Chrome's built-in Translator API only

- Feature-detect `'Translator' in self`; the API requires **Chrome 138+ on desktop**.
- No cloud service, API key, cost, or extension-originated network request. Chrome downloads an on-device language pack when a pair is first used; the page text is not uploaded.
- `minimum_chrome_version` stays **91**. Older Chrome simply does not show the button, and invoking the command shows a short explanation.
- If `Translator` is missing, or the host page's `Permissions-Policy` blocks it, degrade to that explanation rather than a broken panel.
- The API is available in the extension's content script; verified on Chrome 156 during planning.

### 3. Selection first, paragraph on Shift

- Default scope is the current selection, matching the toolbar's existing selection model.
- **Shift-click** translates the block containing the selection, using `closestBlock()`. The keyboard shortcut always translates the selection; paragraph scope is a pointer modifier.
- Reuse `buildTextMap(range)` rather than `Range.toString()` so block and inline boundaries keep their word separators.
- The tooltip says: `Translate selection (Alt+Shift+T) · Shift-click: paragraph`.

### 4. The panel owns the target language

- A target-language `<select>` lives in the panel. There is no duplicate control in the options page or the in-page settings dialog in v1.7.0; the panel is where the setting is needed, and a duplicate would risk drift.
- The choice is stored in `chrome.storage.sync` as `translationTarget`, so it follows the profile.
- The source language is derived from the nearest `lang` attribute or the page language, with a manual override in the panel. Do not depend on `LanguageDetector`: it reported `unavailable` on the test Chrome build.

### 5. Non-modal dialog beside the toolbar

- `role="dialog"` with `aria-modal="false"`, labelled by its heading. Focus moves into the panel; Tab follows the normal document order, and Shift+Tab returns to the toolbar; `Escape` closes the panel first and returns focus to **Translate**. A second `Escape` closes the toolbar as before.
- Mount the panel as a sibling of the toolbar under `getMountNode()`, not inside the `role="toolbar"` container, so the toolbar's ARIA pattern stays valid. Add its ID to `isClickOutsideExtensionUi`, `SKIP_SELECTOR`, and the selection-change guard.
- Position it with JavaScript from the toolbar's rectangle: below the toolbar, or above it when the toolbar is above the selection, and clamp it to the viewport. Recalculate on scroll and resize.
- The panel is a snapshot: changing the page selection while it is open does not replace its contents. Closing and translating again takes a new snapshot.

### 6. Plain text, 5,000-character cap

- Use `Translator.translate()` for v1.7.0. Streaming is deferred so the result is announced once, not on every chunk.
- Cap input at **5,000 characters** after whitespace normalization. Longer input shows the character count and asks the user to select less text or use the paragraph scope.
- Links, emphasis, lists, and line breaks are flattened in the panel. This is documented; the original remains on the page.

## UX

### Toolbar

Add one icon button to the existing reading group, before **Read Aloud**:

```text
[Font] [Spacing] [Contrast] [Translate] [Read Aloud] [Stop]
```

- Visible label: `文A` (the conventional translate glyph), with `aria-label="Translate"`.
- Tooltip: `Translate selection (Alt+Shift+T) · Shift-click: paragraph`.
- `aria-busy="true"` and a static `…` while a request is in flight. No animated spinner under `prefers-reduced-motion`.
- Add the in-page `Alt+Shift+T` shortcut beside the existing Alt+Shift+B/H/R shortcuts. It is ignored in editable fields and when there is no saved selection, and it always uses the selection scope.

### Panel

```text
┌ Translation ──────────────────────── ✕ ┐
│ From [Auto (Spanish) ▾]  To [English ▾] │
│ Preparing language pack… 42%            │
│                                         │
│ <translated text, lang="en" dir="auto"> │
│                                         │
│ ▸ Original text                         │
│ [Copy] [Read aloud]                     │
└─────────────────────────────────────────┘
```

- Header: **Translation** and a close button.
- Language row: source and target selects with visible labels. Stack them on narrow viewports.
- Status line: `role="status"` and `aria-live="polite"` for “Translating…”, download progress, and “Translation ready”. Throttle progress announcements to 25% steps.
- Result: plain text with `lang` set to the target and `dir="auto"`. Focusable (`tabindex="0"`) so keyboard users can scroll a long result.
- **Original text** is a collapsed `<details>` block, also carrying its own `lang`.
- **Copy** and **Read aloud** are disabled until a result exists.
- Errors use `role="alert"` and offer **Try again**. Changing either language cancels the current request and starts a new one.
- Copy uses `navigator.clipboard.writeText` in the click handler. If the API is unavailable or denied, select the result and tell the user to press Ctrl/Cmd+C.
- Read aloud uses the target language for chunking, sentence splitting, and voice choice. If page reading is already active, stop it first.

### Focus and selection guards

- Opening the panel focuses the panel container (`tabindex="-1"`) so the screen reader announces the dialog and its label; Tab then reaches the language selects and actions.
- Add a `STATE.translationOpen` guard to `handleSelectionChange` so clicking non-focusable panel text cannot tear down the toolbar.
- Prevent the default on `mousedown` for panel buttons (but not the selects), so Copy, Read aloud, and Close do not collapse the page selection. The panel is outside the toolbar, so it does not inherit the toolbar's handler.
- Because the panel is outside the toolbar element, its selects keep native arrow-key behavior and the toolbar's roving handler does not see them.
- The close button, Escape, and clicking outside the extension UI all close the panel. Closing does not stop speech that is already playing; the toolbar's **Stop Reading** remains available.

## API handling

- `Translator.availability({sourceLanguage, targetLanguage})` returns `available`, `downloadable`, `downloading`, or `unavailable`.
- Call `Translator.create()` directly from the click path so the first download has user activation. Cache one translator per language pair for the page lifetime.
- Pass an `AbortSignal`; closing the panel, changing a language, or starting a new request aborts the old one.
- The first download reports progress through `monitor`; show a percentage, keep the panel usable, and offer cancel.
- Translation calls are sequential. Disable duplicate submissions rather than queueing them.
- Normalize BCP 47 tags before use: strip most regions (`pt-BR` → `pt`), map `zh-CN` → `zh`, `zh-TW`/`zh-HK` → `zh-Hant`, and `nb` → `no`. Persist the normalized tag.
- Supported languages come from Chrome's published list (about 40). If Chrome adds pairs, they can be added to the static table; there is no API to enumerate them.
- If the source and target are the same, show “This text is already in English” and do not call the API.

## Architecture

New files:

- **`content-scripts/modules/translation.js`** — DOM-free language table, normalization, target default, availability/create/translate wrapper, translator cache, abort and error mapping. Accepts an injectable translator factory so it can be unit-tested in Node.
- **`content-scripts/modules/translation-ui.js`** — panel markup, language controls, status/result rendering, copy, read-aloud wiring, focus handling, viewport placement.

Touched files:

- `core.js`: panel ID, input cap, `STATE.translationOpen`.
- `toolbar.js`: button, command routing, tooltip, and the panel ID in `isClickOutsideExtensionUi`.
- `commands.js`: `translate` command; no history entry.
- `scope.js`: Shift flips `translate` from selection to block scope.
- `app.js`: selection guard, `Alt+Shift+T`, close on outside click.
- `reading.js`: extract a text-based reading path so the panel can speak plain text with a target language without a page range or highlight map.
- `prefs.js`: `translationTarget` in `SYNC_KEYS`; normalize on load.
- `settings-io.js`: `translationTarget` in `PREFERENCE_KEYS` and `buildSettingsFile`.
- `content.css`: panel, light/dark, forced-colors, narrow viewport, reduced motion.

No manifest permission changes and no new web-accessible resources.

## Storage and schema

| Key | Values | Default |
|-----|--------|---------|
| `translationTarget` | normalized BCP 47 tag from the supported list | `navigator.language` normalized, else `en` |

- Bump `CONFIG.settingsSchemaVersion` to **4**.
- Export `translationTarget` under `preferences`; older schema files import their known keys and leave the current target unchanged.
- Update the hardcoded schema assertions in `check-v140.js`, `check-v141.js`, and `check-v150.js`, plus the options export tests.
- The source language is session-only and is not exported.
- No page text, translation result, or selection is stored. The panel clears on close.

## Accessibility contract

- The button has the accessible name **Translate**; the tooltip names both scopes and the shortcut.
- The panel is a labelled dialog; focus moves in and returns to the button on close.
- Source and target selects have programmatic labels; language names are readable English names.
- The result has `lang` and `dir="auto"` so screen readers use the right pronunciation and direction.
- Progress is polite; errors are assertive; the result is not re-announced on every chunk.
- Copy and read-aloud disabled states are announced.
- Keyboard-only path: select text, focus the toolbar, activate Translate, change languages, copy, read, close.
- Forced-colors uses `Canvas`/`CanvasText` for the panel, `ButtonFace`/`ButtonText` for controls, and `Highlight` for focus.
- Works at 200% zoom and on a 320 px-wide viewport without clipping the close button or the result.

## Errors and edge cases

| Situation | Behaviour |
|---|---|
| `Translator` missing or blocked | Hide the button; if invoked, toast: “Translation needs Chrome 138 or newer on desktop.” |
| Pair unavailable | Panel message: “Chrome can't translate Spanish to English yet.” Keep the selects usable. |
| First download | Progress and cancel; retry on failure. Needs the originating click. |
| Download fails or offline | “The language pack couldn't download. Check your connection and try again.” + **Try again**. |
| Same source and target | “This text is already in English.” No API call. |
| Empty selection | Toast: “Select text or a paragraph to translate.” |
| Over 5,000 characters | Message with the count; suggest a smaller selection or Shift paragraph. |
| Source language unknown | Select “Auto” shows “Choose the source language”; Translate stays disabled until chosen. |
| Translation returns empty | Treat as an error and offer retry. |
| Selection detached by a re-render | Capture the text at open time; if the range is gone, use the live selection or ask for a new one. |
| Page navigates or content script unloads | Panel disappears with the page; no persistence. |
| Clipboard denied or insecure page | Select the result and prompt for Ctrl/Cmd+C. |
| Editable field | Do not open; the toolbar does not appear for editable targets. |
| Cross-origin iframe | Out of scope: the content script runs in the top frame only. |

## Risks and mitigations

| Risk | Mitigation |
|------|------------|
| API availability varies by Chrome version, policy, or page `Permissions-Policy` | Feature-detect, explain, never break the rest of the toolbar; test a blocked page |
| First-use download is slow or fails | Progress, cancel, retry, and a clear offline message |
| Language coverage is incomplete | Static supported list and a pair-specific message |
| Machine translation quality | Label the result as machine translation; keep the original one click away |
| Panel covers page text | Viewport clamping, flip above/below, max-height with scrolling, close button |
| Toolbar crowding | One icon button in the reading group; test at 320 px |
| Selection/focus interactions remove the toolbar | `translationOpen` guard, `mousedown` prevention on panel buttons, panel added to the outside-click check |
| Reading refactor regresses page reading | Keep existing reading tests and add text-session tests |
| Schema bump breaks old import tests | Update schema assertions and add a schema 3 → 4 import case |
| Privacy wording drifts | State that the extension sends nothing; Chrome downloads the pack |

## Test plan

**Node**

- `check-translation.js`: tag normalization, target default, language table, character cap, same-language guard, cache keys, abort, and error mapping with a fake translator.

**Browser**

- New `check-v170.js` using the content script in the page world with a fake `Translator`, plus `content.css`:
  - Button hidden when `Translator` is absent; present when it exists.
  - Clicking sends the selected text and renders a result with the correct `lang`/`dir`.
  - Shift uses the paragraph text and the paragraph label.
  - Target language saves and survives a reload.
  - Source defaults from `<html lang>` and can be overridden.
  - Availability `unavailable`, download progress, failure + retry, cancel, and same-language paths.
  - 5,000-character cap message.
  - Copy path and clipboard fallback.
  - Read aloud receives the translated text and target language.
  - Escape closes the panel and returns focus; Tab moves through the panel; selects keep native arrow keys.
  - Clicking inside the panel does not dismiss the toolbar; clicking the page closes both.
  - Collapsing the page selection while the panel is open keeps it open.
  - No page text mutation and no new history entry.
  - Forced-colors, light, dark, 320 px width, and 200% zoom.
- Extend `check-a11y-tree.js` with the button, panel, selects, result, and status names.
- Extend `check-forced-colors.js` with the panel and its controls.
- Real-extension smoke: the button appears on a normal page and the API is detected; do not trigger a model download in the automated suite.
- Update schema assertions and add a schema 4 round-trip in `check-options.js` or `check-v170.js`.
- Full `run-all.ps1` must be green.

**Manual**

- NVDA: open the panel, hear the pair, progress, result language, error, and copy confirmation.
- Keyboard-only: select, open, change languages, copy, read aloud, close.
- One real first-use download, then an offline second use.
